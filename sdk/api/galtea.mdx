## Galtea

The `Galtea` class is the main entry point for the Galtea SDK. It provides access to all the functionalities of the SDK.

### Initialization

To initialize the `Galtea` class, you need to provide your API key obtained in the [settings page](https://platform.galtea.ai/settings) of the Galtea platform.

```python
galtea = Galtea(api_key="YOUR_API_KEY")
```

### Services

The `Galtea` class provides access to the following services:

- [`products`](/sdk/api/product/service): Access [product](/concepts/product) related functionalities.
- [`endpoint_connections`](/sdk/api/endpoint-connection/service): Access [endpoint connection](/concepts/product/endpoint-connection) related functionalities.
- [`phone_connections`](/sdk/api/phone-connection/service): Access [phone connection](/concepts/product/phone-connection) related functionalities.
- [`web_rtc_connections`](/sdk/api/webrtc-connection/service): Access [WebRTC connection](/concepts/product/webrtc-connection) related functionalities.
- [`storage`](/sdk/api/storage/service): Move files between this machine and the platform's object storage.
- [`versions`](/sdk/api/version/service): Access [version](/concepts/product/version) related functionalities.
- [`datasets`](/sdk/api/dataset/service): Access [dataset](/concepts/product/dataset) related functionalities.
- [`test_cases`](/sdk/api/test-case/service): Access [test cases](/concepts/product/dataset/test-case) related functionalities.
- [`metrics`](/sdk/api/metric/service): Access [metric](/concepts/metric) related functionalities.
- [`models`](/sdk/api/model/service): Access [model](/concepts/model) related functionalities.
- [`sessions`](/sdk/api/session/service): Access [session](/concepts/product/version/session) related functionalities.
- [`traces`](/sdk/api/trace/service): Access [trace](/concepts/product/version/session/trace) related functionalities.
- [`spans`](/sdk/api/span/service): Access [span](/concepts/product/version/session/span) collection and management.
- [`evaluations`](/sdk/api/evaluation/service): Access [evaluation](/concepts/product/version/session/evaluation) related functionalities.
- [`runs`](/sdk/api/run/service): Group the sessions and evaluations of one launch into a [run](/concepts/product/run).
- [`jobs`](/sdk/api/job/service): Inspect and cancel async jobs (e.g. inference batches started by `evaluations.run()`).
- [`simulator`](/sdk/api/simulator/service): Access [conversation simulator](/concepts/product/dataset/test-case/conversation-simulator) related functionalities.

### Example

```python
products = galtea.products.list(limit=10)
```

### Errors

Every call reaches the platform over HTTP, so a failure arrives as a `requests` exception.

When the platform holds nothing under the id or name you passed, the SDK raises
`EntityNotFoundException`. It covers every service: `products.get`, `versions.get_by_name`,
`sessions.get_by_custom_id` and the rest all report a missing entity the same way.

Import it with `from galtea import EntityNotFoundException`.

```python
try:
    version = galtea.versions.get_by_name(product_id=product_id, version_name=version_name)
except EntityNotFoundException:
    version = galtea.versions.create(product_id=product_id, name=version_name)
```

`EntityNotFoundException` is the name to catch. It covers both ways the SDK learns that nothing
matched, so you never have to know which one happened.

<Note>
  Only a 404 that names an entity becomes `EntityNotFoundException`. A 404 for a path the API does
  not serve stays a plain `requests.HTTPError`, so a typo in a base URL never reads as a missing
  record. Every other status stays a plain `requests.HTTPError` too.
</Note>

Read the status from `e.status_code`. It is always 404.

### When you need the response

The SDK learns that an entity is missing two ways, and raises a different class for each. Both are
`EntityNotFoundException`, so catching that name is enough unless you want the difference.

| Raised | When | Carries |
|---|---|---|
| `EntityNotFoundException` | a lookup by name found no match in a list the API returned in full | the message and `status_code` |
| `EntityNotFoundHTTPError` | the API answered 404 | those, plus `response` and `request` |

`EntityNotFoundHTTPError` also derives from `requests.HTTPError`, so a program that already catches
`requests.HTTPError` around a `get()` call keeps catching it. Nothing forces you to migrate.

The plain `EntityNotFoundException` is not a `requests.HTTPError`, because no request failed: the
API answered normally and the name was simply not in the result. Reach for `response` only after
catching `EntityNotFoundHTTPError`, where it is always present.
