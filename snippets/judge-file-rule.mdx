<Note>
  **A metric scores a file only when its judge model reads that kind of file.** Only a [Galtea file](/concepts/product/version/session/content-parts#galtea-files), one you uploaded to Galtea or one that Galtea stored from inline media, is sent to a judge. A file on your own host is stored as sent and is never sent to a judge as a file, so it never skips an evaluation: the judge reads its entry as JSON text, in its place in the turn. The kinds a judge reads depend on its model, and the model picker of the metric form shows them for each model. A judge is sent PNG, JPEG, WebP, GIF and PDF files as files. Every LLM judge model reads a text file (TXT, CSV, Markdown, JSON, XML or HTML, or a file of another type whose bytes are text) as its text: the evaluator decodes it and sends the text after the metric's prompt, under the file's name and number. A DeepEval-based metric reads no file, a text file included. A `data:` URI inside that text is replaced with `[inline <type> data removed]`. The other accepted types, such as DOCX, XLSX or TIFF, are stored, and a Galtea input file of those types still reaches your endpoint, but no judge reads them. The rule is the same for the input and the output, and a metric that reads `conversation_turns` reads both sides of every turn. A metric that reads `traces` also reads the Galtea files of every span, and a metric that reads `retrieval_context` reads the Galtea files in the output of `RETRIEVER` spans.

  **Galtea numbers the files of a session.** Turn files come first, in turn order, input before output. The files of every span come next, in span start order. A file that sits in several places of a session takes one number, at its first place, and the judge receives it once. The judge reads each file in its place in the text as `[File N]`, and the session page and the span page show the same `File N` beside each Galtea file.

  Before an evaluation runs, Galtea checks every Galtea file on each side the metric reads. One file the judge would not read skips the evaluation, whatever text sits beside it. A skipped evaluation costs no credits, and its reason names the file with its number, its turn and what refused it:

  - The judge model cannot read that kind of file.
  - The model catalog does not say whether the judge model reads it.
  - The metric names no judge model.
  - The metric is DeepEval-based: those judges are sent the turn text only, not a file.
  - The metric is deterministic: it compares text without a model.
  - The metric is a [classifier](/concepts/metric/classifier) metric and the file is not a text file: a classifier gets the text of a text file, and no image or PDF.
  - The file is a type no judge reads, such as DOCX, XLSX or TIFF, or an audio file: a judge reads audio only through its transcript.

  When the evaluator then reads a Galtea file to send it, it skips the evaluation if the file no longer exists in storage, is empty, or is larger than the 20 MB a judge can receive, and for a text file if its bytes are not text. The evaluator reads UTF-8 (the default), UTF-16 with a byte order mark, and windows-1252 (also named ISO-8859-1 or Latin-1). A file that declares another charset, such as ISO-8859-2, skips although its bytes are text in that charset. The reason names the file. For an LLM judge, Galtea adds no other size limit for text: the file text counts toward the judge model's context window like the rest of the session. When the session does not fit, the model refuses the call and the evaluation fails, as for a long conversation. A classifier metric has its own size limit: see its [limits](/concepts/metric/classifier#limits).

  On deployments that send files to the judge, the evaluator also skips an evaluation before it reads any file when the files, on every side the metric reads, total more than one evaluator can hold at once. The reason gives the total and that limit. An evaluation with large files can wait for memory on a busy evaluator before it runs. The wait lasts up to about 25 minutes. After that the evaluation fails as a platform error, and you can retry it.

  Audio input with no transcript is a separate case. A metric that reads the input is skipped when no turn of the session has input text or a Galtea input file, and a turn's audio carries no transcript. Text or a Galtea file on another turn is enough, and the reason, `Evaluators read an audio input through its transcript, and no turn carries one.`, names no file.

  Human evaluation and self-hosted metrics are never skipped for a file or for audio. On deployments that do not send files to the judge, the evaluator also skips a metric whose judge would read the file, and the reason names the file.

  To have the content scored, pick a metric whose judge model reads that kind of file, or log the text your pipeline extracted as the turn input or output, without the file. See [Troubleshooting skipped evaluations](/concepts/metric/evaluation-parameters#troubleshooting-skipped-evaluations).
</Note>
