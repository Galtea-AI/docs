## Platform Improvements

We are working on a new version of the platform, and it will come out soon. In the meantime, this release collects a set of smaller improvements.

- **More intuitive table row behavior:** Clicking anywhere in a table row now opens that row. Before, clicking a shortened cell opened a dialog with the full text instead, which got in the way of simply moving around. The full text is still one click away, from a small button in the cell's top-right corner: shown on hover or keyboard focus, always shown on touch, and present only when the text is really cut off.

- **More evaluator models available in the platform:** An *evaluator model* is the LLM that scores a [metric](/concepts/metric). You can pick from the GPT-5 family (`GPT-5.2`, `GPT-5.1`, `GPT-5`, `GPT-5-mini`) and five EU data zone models (`eu.claude-sonnet-4-5`, `eu.gpt-4.1`, `eu.gpt-4.1-mini`, `eu.gpt-4o`, `eu.gpt-4o-mini`) that run on European infrastructure, for when your data must stay in the EU. See the [full list](/sdk/api/metric/create#param-evaluator-model-name). `Claude-Sonnet-3.7` and `Gemini-2.0-flash` were disabled in May and can no longer be used. Model names are case-insensitive.

- **API keys verify about 400 ms faster:** Every request authenticated with a `gsk_` API key spent around 400 ms checking that key before doing any work. That check is now near-instant, so the [Python SDK](/sdk/usage), the [CLI](/cli/usage), and trace ingestion all answer faster. Your existing keys keep working and their format is unchanged, so there is nothing for you to update.

- **Retiring an evaluator model now retires the metrics built on it:** When Galtea stops serving an evaluator model, every [metric](/concepts/metric) that uses it is reported as legacy or disabled on its own, instead of each one being marked by hand. If the model comes back, so do the metrics. In the SDK, a `Metric` now carries `disabled_at` next to `legacy_at`. A `disabled_at` date in the future is how an upcoming retirement is announced, so compare it against the current time before treating a metric as disabled.

- **An evaluation that names an unknown evaluator model now fails instead of scoring:** Asking for an evaluator model the platform does not serve returns an error. Before, the evaluation fell back to a default model and returned a normal-looking score, so a result could come from a judge you did not choose.

- **A monitor's Sessions and Evaluations tabs show their rows again:** Both tabs read zero over an empty table. Neither was asking for production traffic, which is the only kind a [Monitor](/concepts/product/monitor) scores. Both now do, and each tab's count is built from the same filters as the table under it, so a count can no longer disagree with the rows it sits above.

- **The Platform version card covers every service:** The **Platform version** card at the end of the **Settings** page listed only the API. It now has one row for the dashboard, one for the API, and one for each of the ten backend services, each showing a readable name plus the exact identifier used in logs and deployments. A service that has not reported its version yet says so, with a tooltip explaining what to check, rather than showing a blank version that would make it look healthy. Visible to enterprise members and admins.
