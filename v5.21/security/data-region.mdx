## Overview

The data region of an organization tells Galtea where it may process the data of that organization, such as the requests to model providers that run evaluations, generate test data and simulate conversations.

An organization has one of two regions:

- **Global** is the default. Galtea processes your data with its normal routing.
- **EU only** asks that the processing of your data stays in the European Union. "EU-only processing" here has the meaning described in [European models, EU-only processing, and the difference between them](/v5.21/deployment/cloud-specifics#european-models-eu-only-processing-and-the-difference-between-them). It is a rule about *where* the processing happens, not about *who* the model provider is.

The region applies to the model calls that Galtea makes for your organization through its LLM gateway: the jobs of the AI services (test generation, evaluations by a judge model, conversation simulation, metrics, reports and the platform assistant) and the model calls of the platform API itself. The region of the organization that owns the data decides, not the region of the person who starts the job. A request that names no product yet, such as product setup, the form check, a cURL import, the model settings check and the platform assistant, uses the region of the signed-in user's organization. If an EU-only call cannot be served in the EU, it fails instead of running elsewhere. A job fails. The way an API request fails depends on the call:

- A model call that the API makes itself answers `503`. This covers product setup, the form check, a cURL import, the model settings check, the test name and the production trace insights.
- A request that the API passes to another AI service answers `502`. This covers the metric completion, update and conversion calls, and the next simulated user message.
- The platform assistant chat answers `200` and sends an error event with the code `upstream_failure`.

The region does not cover the calls that Galtea sends to your own endpoint, and it does not cover the public docs assistant, which has no organization. In voice tests, speech-to-text runs on the Speechmatics EU endpoint, which the deployment sets by default, and text-to-speech runs on an EU endpoint for an EU-only organization. A voice test of an EU-only organization fails when the deployment's text-to-speech provider has no EU endpoint. The region does not yet cover the telephony provider, which carries the call audio. The decision model is covered: the evaluations of [decision metrics](/v5.21/concepts/metric/decision-model), their "Test on a sample" preview and the [applicability check](/v5.21/concepts/metric#applicability-check) of an EU-only organization run on an EU deployment of the model. A decision metric whose decision model has no EU deployment ends SKIPPED for an EU-only organization, and its preview fails, with no call to another region. The applicability check never sends data outside the EU, and it is the one exception to failing an EU call: when the deployment has no EU decision model for it, or the EU model cannot answer in time, the check gives no verdict and the metric is judged.

<Info>
  The data region is an **Enterprise feature**. Contact [support@galtea.ai](mailto:support@galtea.ai) to enable it for your organization.
</Info>

<Note>
  The region does not change where Galtea stores your data. Storage stays in `eu-west-1` for shared SaaS, in the region you choose for a private tenant, and in your own infrastructure when self-hosted. See [Security assurance](/v5.21/deployment/security-assurance). The region covers data processing only.
</Note>

<Note>
  This feature is not live yet. A deployment turns it on with a setting that is off by default. While the setting is off, the organization settings page shows no region and a request to change the region is refused.
</Note>

## Who can see and change it

- **Owners** can see the current region on the organization settings page. They cannot change it.
- **Galtea staff** change the region on request. Ask [support@galtea.ai](mailto:support@galtea.ai) to switch it.
- The region can only be changed on an organization with an active Enterprise subscription. An organization that is frozen must be unfrozen first.

## Judge models in an EU-only organization

A metric runs on one judge model. In an EU-only organization, that judge needs an EU deployment that answers. Galtea reads this from its LLM gateway and refreshes it on a schedule.

- The judge picker offers only judge models that have an EU deployment. A judge that Galtea has not checked yet is not offered.
- A metric whose judge has no EU deployment shows as **Unavailable** in the dashboard, with the reason. The API returns the reason as `unavailableReason` on the metric, and the field is `null` for a metric that can run. An endpoint that does not read your data region, such as the metrics of a specification, leaves the field out.
- An evaluation of such a metric is skipped with the same reason. It is not run elsewhere.
- A metric keeps its judge. For a metric of your organization, create a revision with another judge: the metric page has a **New Revision** button for this. Galtea manages its own metrics, so you cannot revise one. Create a metric of your own with another judge instead: the metric page has a **Use as Template** button for this. Then run the evaluation again with the new revision or metric.

A metric whose judge Galtea has not checked yet keeps running until the check says the judge has no EU deployment.

A judge has one name in every organization. Its EU deployment can retire on another date than its other deployments, so Galtea warns an EU-only organization with the date of the EU deployment. Each evaluation records the region it ran in, as `dataRegion` in the API.

A decision metric runs on a decision model, and the same rules apply to it. A decision model has an EU deployment when the model itself or its EU copy answers in the EU. The decision model picker offers only those, and the metric shows as **Unavailable** with the name of the decision model in the reason.

## What a switch means

The dashboard asks for a confirmation before it switches the region. Galtea records each change of value in the audit log, with the old and the new value.

The two changes mean the following:

- **Global to EU only:** from then on, Galtea processes your organization's data in the EU only. Check that the judge models of your metrics have an EU deployment, because a metric on a judge that has none cannot run for your organization. See [Judge models in an EU-only organization](#judge-models-in-an-eu-only-organization).
- **EU only to global:** Galtea goes back to its normal routing, which may process your data outside the EU.

A change applies to processing that starts after it. It does not change processing that already ran.
