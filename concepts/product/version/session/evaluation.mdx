## What is an Evaluation?

An evaluation in Galtea represents the assessment of traces from a [session](/concepts/product/version/session) using the evaluation criteria of a [metric](/concepts/metric). Evaluations are now directly linked to sessions, allowing for comprehensive evaluation of full sessions containing multiple traces for multi-turn dialogues.

<Note>Evaluations do not call your AI product — they score outputs that have already been generated. Run your product first to produce outputs, then trigger the evaluation to score them.</Note>

You can create evaluations from the [Galtea dashboard](https://platform.galtea.ai/) (using [Endpoint Connections](/concepts/product/endpoint-connection)) or programmatically using the [Galtea SDK](/sdk/api/evaluation/service).

Every launch you trigger creates a [Run](/concepts/product/run), and each evaluation of that launch points back at it. An evaluation produced by a [Monitor](/concepts/product/monitor) has no Run, because it comes from a rule instead of a launch.

## Results Excluded from Analytics

A metric revision can be excluded from analytics. Its evaluations stay available and keep their original score, reason, and status. They stop contributing to scores, coverage, insights, and monitor aggregates.

The evaluation list hides these results by default. Turn on **Show excluded from analytics** to reveal them. Add the **Analytics** column from the **Columns** menu to see which results are excluded. An excluded evaluation's detail page explains who excluded its metric revision and when, then links to the metric where you can restore it.

Exclusion belongs to the metric revision, not to one evaluation. Restoring that revision returns all its results to analytics.

## Evaluation Lifecycle

Evaluations follow a specific lifecycle:

<Steps>
  <Step title="Creation">[Trigger an evaluation](/sdk/tutorials/run-dataset-based-evaluations). It will appear in the session's details page with the status "pending"</Step>
  <Step title="Processing">Galtea's evaluation system processes the evaluation using the evaluation criteria of the selected [metric](/concepts/metric)</Step>
  <Step title="Completion">Once processed, the status changes to "completed" and the [results](/concepts/product/version/session/evaluation#evaluation-properties) are available</Step>
</Steps>

## Evaluation Properties

### Result Properties

Once an evaluation completes, the following fields are available:

<ResponseField name="Status" type="Enum">
  The current status of the evaluation.
  Possible values:
  - **Pending**: The evaluation has been created but not yet processed.
  - **Pending Human**: The evaluation is waiting for a human annotator to review and score it. This status is used for metrics with `source: "human_evaluation"`.
  - **Success**: The evaluation was processed successfully.
  - **Failed**: The evaluation encountered an error during processing. Check the `canRetry` field to determine if this evaluation can be retried.
  - **Skipped**: The evaluation could not produce a score. The error message names the cause. Common causes are:
    - Metric validation failed, for example a required parameter is missing.
    - The organization ran out of credits.
    - The metric could not read the actual output, for example plain text where [JSON Field Match](/concepts/metric/json-field-match) expects a JSON object.
    - The judge model was unavailable.

    Check the `canRetry` field to see whether the evaluation is eligible for a retry. A retry re-scores the output already stored on the session. When the cause is that output, send a new inference result instead.
  - **Cancelled**: The evaluation was deleted while it was still waiting to be scored, so the platform stopped it before it produced a score. Deleting the evaluation, or something it belongs to such as its session, its run or its metric, cancels every pending evaluation the delete removes. The same step deletes the evaluation, so it no longer appears in lists. Cancelling a run does not cancel its evaluations.
  - **Outdated**: The evaluation was produced by a [Monitor](/concepts/product/monitor), and the session then reopened and gained a new turn. The score describes an older version of the conversation, so it no longer counts as current: charts and averages leave it out, and the monitor scores the session again once it closes. The row keeps its score and its reason, so you can still read what it found.
</ResponseField>

<ResponseField name="Score" type="Number">
  The score assigned to the output by the metric's evaluation criteria. **Example**: 0.85
</ResponseField>

<ResponseField name="Reason" type="Text">
  The explanation of the score assigned to the output by the [metric's](/concepts/metric) evaluation criteria.
</ResponseField>

<ResponseField name="Error" type="Text">
  The error message if the evaluation failed during processing.
</ResponseField>

<ResponseField name="Retries Attempted" type="Number">
  The number of retry attempts made for this evaluation. Starts at 0 and increments each time the evaluation is retried. Used to track retry history and enforce retry limits.
</ResponseField>

<ResponseField name="Can Retry" type="Boolean" default="false">
  Indicates whether the evaluation is eligible for the retry operation. When `false`, it cannot be retried at all. When `true`, it can, but a retry does not always help: `canRetry` is a permission, not a promise. A retry re-scores the output already stored on the session, so it succeeds for a temporary cause (an evaluation processing error, insufficient credits, a judge model that was unavailable) and skips again when the cause is the stored output itself. Defaults to `false`.
</ResponseField>

<ResponseField name="Launched By" type="User" optional>
  The user who launched this evaluation, read-only and set by the API. For an evaluation launched through the SDK, this is the owner of the API key used. Null for a [Monitor](/concepts/product/monitor)-dispatched evaluation.
</ResponseField>

<ResponseField name="Run ID" type="Text" optional>
  The ID of the [Run](/concepts/product/run) that launched this evaluation (`runId` in the API). It is empty for an evaluation produced by a [Monitor](/concepts/product/monitor), because an evaluation carries a Run or a Monitor, never both. A retried evaluation keeps the Run it was created with.
</ResponseField>

<ResponseField name="Product ID" type="Text" optional>
  The ID of the [product](/concepts/product) whose session produced this evaluation, read-only and set by the API. Useful when a list spans several products, for example listing every evaluation for one metric.
</ResponseField>

<ResponseField name="Judge Input Tokens" type="Number" optional>
  The tokens the judge model received to score this evaluation, read-only and set by the API. It covers the metric prompt and the session content. Null when the judge model reported no usage, which is different from 0.
</ResponseField>

<ResponseField name="Judge Output Tokens" type="Number" optional>
  The tokens the judge model produced to score this evaluation, read-only and set by the API. The judge's total is `judgeInputTokens` plus `judgeOutputTokens`. Null when the judge model reported no usage.
</ResponseField>

<ResponseField name="Judge Reasoning Tokens" type="Number" optional>
  The part of `judgeOutputTokens` the judge model spent on reasoning, read-only and set by the API. It is a subset of the output tokens, so do not add it to the total. A judge model that does not reason reports 0, not null. Null means no reasoning count was recorded, which almost always means the whole measurement is missing and the other two fields are null too.
</ResponseField>

<Note>These token counts measure the judge model, not your AI product. They are not Galtea credits: Galtea charges a flat credit cost per evaluation. Use them to predict what the same judge costs on your own model provider.</Note>

<ResponseField name="Human Evaluator ID" type="Text" optional>
  The ID of the human evaluator assigned to this evaluation, if applicable.
</ResponseField>

<ResponseField name="Human Score" type="Number" optional>
  The human-provided annotation score, separate from the AI-generated score. When a human annotates an AI-evaluated metric, this field stores their score without overwriting the original AI score. Once set, this score replaces the AI score in every reported number: analytics, the product score, coverage, and monitor results. A reviewer can remove the annotation again, which clears this field. Where the AI produced a score, every reported number goes back to it. Where the AI produced none, as on a failed, skipped or cancelled evaluation, the evaluation stops being reported at all. The removal is permanent: the score is deleted, not archived, so getting it back means annotating the evaluation again.
</ResponseField>

<ResponseField name="Human Reason" type="Text" optional>
  The human-provided annotation reason, separate from the AI-generated reason. When a human annotates an AI-evaluated metric, this field stores their reasoning without overwriting the original AI reason. Galtea reports this reason wherever it reports the human score. Leave it blank, and the reported reason is blank too; it never falls back to the AI reason. Removing the annotation clears this field with the human score.
</ResponseField>

<ResponseField name="Human Evaluator Started At" type="Text" optional>
  The timestamp when the human evaluator started reviewing this evaluation, if applicable.
</ResponseField>

<ResponseField name="Human Evaluator Finished At" type="Text" optional>
  The timestamp when the human evaluator submitted their evaluation or annotation.
</ResponseField>
