This page covers the detailed configuration for [Endpoint Connection](/concepts/product/endpoint-connection) request formatting, response extraction, retry behavior, and conversation end rules.

## Input Template

The Input Template is a [Jinja2](https://jinja.palletsprojects.com/) template string that defines how Galtea formats the request body before sending it to your endpoint.

<Tip>
  For a detailed guide on structured input syntax (`{{ input.field_name }}`), context fields, JSON escaping, the placeholder toolbar, and missing field behavior, see the [Structured Input Template Syntax](/concepts/product/endpoint-connection-template-syntax) reference.
</Tip>

### Available Placeholders

| Placeholder | Description |
|-------------|-------------|
| `{{ input.<field> }}` | Access a field from the test case input, e.g. `{{ input.user_message }}` (required) |
| `{{ context.<field> }}` | Access a field from the test case context, e.g. `{{ context.topic }}` |
| `{{ session_id }}` | The external session ID (if available) |
| `{{ test_case_id }}` | The test case ID |
| `{{ dataset_id }}` | The id of the [Dataset](/concepts/product/dataset) |
| `{{ galtea_session_id }}` | The Galtea session ID |
| `{{ trace_id }}` | The id of this turn's [Trace](/concepts/product/version/session/trace), labeled "Galtea Trace ID" in the dashboard. Also sent automatically as the `X-Galtea-Inference-Id` HTTP header -- useful for [span collection](/sdk/tutorials/tracing-agent-operations) |
| `{{ language_code }}` | Full BCP-47 language tag of the test case, region included (e.g. `"es"` or `"es-MX"`). Empty string when no language is set. |
| `{{ language_name }}` | English name of the test case language, with the region when the tag has one (e.g. `"Spanish"` or `"Spanish (Mexico)"`). Empty string when no language is set. |
| `input_files` | [Files and audio attached to the test case input](/concepts/product/endpoint-connection-template-syntax#attached-files-and-audio), one entry per attachment. Each exposes `url`, `base64`, `filename` and `mime_type`, e.g. `{{ input_files[0].url }}` |
| Any metadata key | Any field stored in session metadata (e.g., `{{ sessionId }}`, `{{ tenant }}`, `{{ conversation_token }}`) |

<Note>
  `{{ trace_id }}` and `{{ dataset_id }}` were named `{{ inference_result_id }}` and
  `{{ test_id }}` before version 5.0.0, and the old names still resolve. See
  [Dataset, Trace, and Span Renames](/sdk/migration-guides/entity-renames).
</Note>

### Conversation History

Use `{% for turn in past_turns %}...{% endfor %}` to loop through previous conversation turns. Each turn exposes:
- `{{ turn.input }}` — Previous user input
- `{{ turn.output }}` — Previous assistant response

### Attached Files

Use `{{ input_files[0].url }}` to send an attached file to your endpoint, or `{{ input_files[0].base64 }}` to send its bytes inline. See [Attached Files and Audio](/concepts/product/endpoint-connection-template-syntax#attached-files-and-audio) for the full rules, including the 15-minute URL lifetime.

### Examples

**OpenAI-compatible format:**
```jinja2
{
  "model": "gpt-4",
  "messages": [
    {"role": "system", "content": "You are a helpful assistant."},
    {% for turn in past_turns %}
    {"role": "user", "content": "{{ turn.input }}"},
    {"role": "assistant", "content": "{{ turn.output }}"},
    {% endfor %}
    {"role": "user", "content": "{{ input.user_message }}"}
  ]
}
```

**Previous queries array:**
```jinja2
{
  "model": "gpt-4",
  "previous_queries": [
    {% for turn in past_turns %}
    "{{ turn.input }}"{% if not loop.last %},{% endif %}
    {% endfor %}
  ],
  "current_query": "{{ input.user_message }}"
}
```

**Custom format:**
```jinja2
{
  "data": {
    "names": ["query", "contexto"],
    "ndarray": [
      [
        "{{ input.user_message }}",
        [
          {% for turn in past_turns %}
          "{{ turn.input }}",
          "{{ turn.output }}"{% if not loop.last %},{% endif %}
          {% endfor %}
        ]
      ]
    ]
  }
}
```

<Note>
  When a loop is the **last item** in a JSON array, use `{% if not loop.last %},{% endif %}` after each iteration to prevent a trailing comma. When there's content **after** the loop (like in the OpenAI example above), trailing commas are valid and this pattern is not required.
</Note>

## Output Mapping

A JSON object defining how to extract values from the API response using [JSONPath](https://goessner.net/articles/JsonPath/) expressions.

### Special Keys

| Key | Behavior |
|-----|----------|
| `output` | **Required.** The AI's response content. |
| `session_id` | Stored as the external session identifier, accessible via [`custom_id`](/concepts/product/version/session#session-properties). |
| `retrieval_context` | Stored as a `RETRIEVER` span for RAG evaluations (derived at read time, not a directly-readable field). |
| `traces` | Extracts an array of [span](/concepts/product/version/session/span) objects and stores them linked to the trace. Each object should contain at least a `name` field and can include any of the [Span properties](/concepts/product/version/session/span#span-properties): `type`, `description`, `inputData`, `outputData`, `error`, `latencyMs`, `metadata`, `startTime`, `endTime`. A `type` Galtea does not recognize is normalized to a known span type, and your original label is kept in that span's `metadata` under `galtea.span.original_type`. Galtea stores every valid span and drops only the invalid ones, and shows the [dropped count](/concepts/product/version/session/trace) on the trace. |
| `output_files` | Stores each file your endpoint answers with, such as a generated report, as a Galtea file on the turn's output. The path can match one file or a list of files. See [Files in the Response](#files-in-the-response). |
| Any other key | Stored in session metadata and available as `{{ key }}` in templates. |

### JSONPath Syntax Reference

| Expression | Description |
|------------|-------------|
| `$` | Root object |
| `.` | Child operator |
| `[]` | Array index or child operator |
| `[*]` | Wildcard (all elements) |
| `[0]` | First array element |
| `[-1:]` | The last array element, as a one-element list |

### Example

```json
{
  "output": "$.choices[0].message.content",
  "retrieval_context": "$.choices[0].retrieval_context",
  "session_id": "$.metadata.session_id",
  "traces": "$.metadata.traces",
  "output_files": "$.files"
}
```

### Files in the Response

Use the `output_files` key when your agent answers with a document: a generated report, a filled form, an image. Galtea stores a copy of each file on the turn's output, so a later read always sees the same bytes. A file that is already in Galtea is linked instead of copied. The stored files appear as the trace's [Output Files](/concepts/product/version/session/trace#param-output-files).

Each file the path matches can take one of three forms:

- **Bytes:** an object with `base64` and optional `mime_type` and `filename`, or a `data:` URI string. The standard and the URL-safe base64 alphabets both work. Galtea decodes the bytes and makes no extra request.
- **URL:** an `http(s)` URL string, or an object with `url` (or `uri`) and optional `mime_type` and `filename`. Galtea downloads the file once, during the run.
- **Galtea file:** the canonical storage URI of a file already uploaded to Galtea, as a string or in `url` or `uri`. It is the signature-free `uri` a written trace or test case reads back with. Galtea links the file on the turn, with no download and no copy. A signed link is a URL, not a Galtea file: it is downloaded and copied. That covers the `uri` an SDK upload returns and the `url` of an `input_files` item.

<CodeGroup>
```json Endpoint Response
{
  "answer": "Here is your quote.",
  "files": [
    { "base64": "JVBERi0xLjQK...", "mime_type": "application/pdf", "filename": "quote.pdf" },
    { "url": "https://files.example.com/quotes/1234/terms.pdf" }
  ]
}
```

```json Output Mapping
{
  "output": "$.answer",
  "output_files": "$.files"
}
```
</CodeGroup>

The text still comes from `output`. A response with files and no text is also a valid turn. An empty value (`null`, `[]`, `{}` or an empty string) means the turn has no file.

The rules:

- **Limits:** at most 20 files and 20 MB in total for one output, Galtea files included. The file extension decides the type, and it must be one a [test case input accepts](/concepts/product/dataset/test-case#file-inputs), such as `pdf`, `docx`, `png` or `csv`. A file with no extension takes one from its `mime_type`, or, for a URL, from the `Content-Type` the file host sends. A name that ends in digits only, such as `invoice_2026.09.23`, counts as having no extension.
- **Download time:** all the URL downloads of one output share one time limit, the connection's [timeout](#timeout). A URL file that has not started when that time runs out is refused.
- **No credentials to the file host:** Galtea sends none of the connection's headers or credentials with the download. A file that needs authentication must come back as bytes, or as a presigned URL that carries its own access.
- **Galtea files belong to your organization:** a Galtea file must be an uploaded file of the organization that owns the product. A file of another organization, or a storage URI that does not name an uploaded file, fails the turn. The same holds for a file that no longer exists.
- **Plain HTTP:** an `http://` file URL is downloaded only when the connection acknowledged plain HTTP, or the deployment allows it for every connection (see [HTTP endpoints](/concepts/product/endpoint-connection#http-endpoints)). Private and internal addresses, such as loopback and cloud metadata, are refused, as they are for the endpoint itself.
- **A refused file fails the turn:** the error names the file and the reason, for example `Output file refused: file 2 ("setup.exe"): the type ".exe" is not allowed`. Galtea stores no file of that turn. When the check Galtea makes before a run already receives a file it would refuse, the run is rejected before it starts.
- **Single-turn runs only:** as with [file inputs](/concepts/product/dataset/test-case#file-inputs), a run of more than one turn fails the turn whose response carries a file. The simulated user reads text only, so the conversation would go on as if the agent said nothing. Run the test case as a single turn, or remove `output_files` from the mapping.
- **Conversation connections only:** Initialization and Finalization connections ignore `output_files`.

The **Test Connection** panel lists the files it finds and shows why a file would be refused. It previews a bytes file and a Galtea file, and it never downloads a URL file. It refuses a Galtea file of another organization, but a Galtea file that no longer exists fails only when a run reads it.

<Warning>
  Evaluators cannot read output files yet. A metric that reads the output is skipped unless at least one turn of the session has text and no file. Text sent beside a file does not count, so a single-turn run whose answer carries a file always skips it. See [Output Files](/concepts/product/version/session/trace#param-output-files).
</Warning>

### State Management

If your API returns values that need to be sent in subsequent requests (e.g., `session_id`, `tenant_id`), Galtea can automatically manage this state:

1. **Extract** — Use Output Mapping to pull values from the API response using JSONPath expressions
2. **Store** — Extracted values are saved in the session and become available as template variables
3. **Reuse** — Reference any stored value in the Input Template or URL using `{{ variable_name }}` syntax

<Tip>
  On the first turn, undefined placeholders resolve to empty strings. After the first response, all extracted values become available for subsequent turns.
</Tip>

**Example:** capture `session_id` and `tenant_id` from responses:

<CodeGroup>
```json Output Mapping
{
  "output": "$.text",
  "session_id": "$.session_id",
  "tenant_id": "$.tenant"
}
```

```json Input Template
{
  "role": "user",
  "content": "{{ input.user_message }}",
  "session_id": "{{ session_id }}",
  "tenant": "{{ tenant_id }}"
}
```
</CodeGroup>

## Custom Headers

Custom headers are sent with every request to your endpoint. Header values support placeholder substitution for injecting authentication credentials, so you can place tokens in any header — not just the standard `Authorization` or `X-API-Key` headers.

### Available Placeholders

| Placeholder | Resolves to | Available when auth type is |
|-------------|------------|---------------------------|
| `{{ auth_token }}` | The authentication token | `BEARER` or `API_KEY` |
| `{{ api_key }}` | The authentication token | `BEARER` or `API_KEY` (alias for `{{ auth_token }}`) |
| `{{ bearer_token }}` | The authentication token | `BEARER` or `API_KEY` (alias for `{{ auth_token }}`) |
| `{{ username }}` | The Basic auth username | `BASIC` |
| `{{ password }}` | The Basic auth password | `BASIC` |

Placeholders are **case-insensitive** and work with both `{{ placeholder }}` and `{ placeholder }` syntax.

### Example

```json
{
  "Authorization": "Bearer {{ bearer_token }}",
  "X-Custom-Api-Key": "{{ api_key }}",
  "X-Tenant-Id": "my-tenant"
}
```

<Tip>
  If you define an `Authorization` or `X-API-Key` header in custom headers, Galtea will **not** add the default authentication header — your custom header takes precedence.
</Tip>

### W3C Trace Context Propagation

When W3C trace context propagation is enabled, Galtea adds a `traceparent` header to every request following the [W3C Trace Context](https://www.w3.org/TR/trace-context/) specification. This allows your endpoint to correlate requests with Galtea's spans without any code changes. You can add a `traceparent` key in your custom headers as a placeholder — Galtea will replace its value with the correct trace context at request time.

See [Send OpenTelemetry Traces to Galtea](/sdk/tutorials/send-opentelemetry-traces-to-galtea#how-span-content-maps-to-span-records) for how correlated spans become Span records.

## Timeout

How long Galtea waits for a single HTTP call to your endpoint before giving up. It is applied **per attempt**, so each retry gets the full timeout again.

<ResponseField name="Timeout" type="Number">
  Per-attempt request timeout in seconds. Default: `15`. Maximum: `120` (values above this are rejected at the API).
</ResponseField>

A timeout counts as a retryable failure. If retry is enabled, a timed-out call is retried like any other transient error.

## Rate Limit

The maximum number of requests per minute your backend can handle. Galtea throttles itself to stay under this limit, using a token bucket shared across all of Galtea, so the limit holds even when many runs execute at once.

<ResponseField name="Rate Limit" type="Number">
  Maximum requests per minute. Default: empty, which means **no limit** (no throttling). Set a number only if your backend needs Galtea to slow down.
</ResponseField>

When the limit is reached, Galtea reschedules the call for later. This wait does not use up a retry attempt and does not block other runs.

## Retry Configuration

Configure automatic retry behavior for failed requests. When enabled, Galtea retries requests that fail with a retryable HTTP status code, a timeout, or a network error. A retry wait does not block other runs: the job is rescheduled and the worker is freed while it waits.

<ResponseField name="Retry Enabled" type="Boolean">
  Whether automatic retry is enabled. Default: `true`
</ResponseField>

<ResponseField name="Max Retry Attempts" type="Number">
  Maximum number of retry attempts (`0`-`10`). Default: `1`. These are retries **after** the first call, so N attempts means up to N+1 calls to your endpoint, and **each call uses credits** (the default of 1 means up to 2 calls). `0` is only valid when retry is disabled; with retry enabled the minimum is `1`.
</ResponseField>

<ResponseField name="Initial Delay" type="Number">
  Initial delay in milliseconds before the first retry. Default: `1000` (1 second)
</ResponseField>

<ResponseField name="Backoff Strategy" type="Enum">
  Strategy for increasing delay between retry attempts:
  - `exponential` - Delay doubles with each attempt (recommended)
  - `linear` - Delay increases linearly
  - `fixed` - Constant delay between attempts

  Default: `exponential`

  The delay is always capped at **Max Delay**. With a small Max Delay, exponential and linear growth are clamped to that ceiling after the first retry, so the strategy has little effect. Raise Max Delay to let the delay grow.
</ResponseField>

<ResponseField name="Max Delay" type="Number">
  Maximum delay between retry attempts, in milliseconds. Default: `3000` (3 seconds). Capped at `60000` (60 seconds); values above this are rejected at the API.
</ResponseField>

<ResponseField name="Retryable Status Codes" type="Array of Numbers">
  HTTP status codes that should trigger a retry. Default: `[429, 500, 502, 503, 504]`. Each value must be a valid HTTP status code (`100`-`599`).

  Codes are honored literally with no client-error short-circuit. Adding a deterministic `4xx` code (such as `401`, `403`, or `422`) makes Galtea retry a call that will always fail, which wastes the full retry budget and the credits for each attempt.
</ResponseField>

## Conversation End Rules

Some agents end a conversation on their own and then answer every further message with an error. Without a rule, Galtea reads that error as a failed turn, so the session fails and is never evaluated. A conversation end rule tells Galtea which reply means "the agent ended the conversation". On a match, the session completes with the turns so far and is evaluated.

A rule has a status code and an optional body match. Default: no rules. A connection holds at most 20 rules, and only a `CONVERSATION` connection accepts them.

<ResponseField name="Status Code" type="Number">
  HTTP status code of the reply (`100`-`599`). A `2xx` code needs a body match, because a `2xx` rule without one would end the conversation after the first normal reply.
</ResponseField>

<ResponseField name="Body JSONPath" type="Text">
  Optional. A JSONPath into the response body, starting with `$` (for example `$.error.code`). See [JSONPath Syntax Reference](#jsonpath-syntax-reference). Filter expressions such as `[?(...)]` are refused.
</ResponseField>

<ResponseField name="Expected Value" type="Text">
  Used when a Body JSONPath is set. The first value the path finds must equal this text. An empty Expected Value matches an empty string.
</ResponseField>

### Example

After your agent closes the conversation, it answers every further message with HTTP `409` and this body:

```json
{"error": {"code": "conversation_ended", "message": "This conversation has ended."}}
```

The rule is status code `409`, Body JSONPath `$.error.code`, and Expected Value `conversation_ended`. A `409` with any other `error.code` does not match, so it still fails the turn as before.

### How a reply matches

- Galtea checks the rules **before** the [retry policy](#retry-configuration). A matching reply is never retried, even when its status code is in Retryable Status Codes.
- A reply matches when the status code is equal and, if the rule has a body match, the first value the JSONPath finds is a string, number, or boolean whose text equals the Expected Value. So the number `42` matches the Expected Value `42`.
- A missing field, an object, an array, `null`, or a body that is not JSON never matches.
- Rules apply only to the conversation calls of text sessions. Initialization and finalization calls, voice sessions, and the connection test ignore them.

### What happens to the session

- **A 2xx match with an agent answer**: the reply is a normal agent reply, so that turn stays as the last turn and is scored. This also holds on the first turn and in a single-turn test.
- **A match with no agent answer**: a non-2xx match (such as the `409` above), or a 2xx match whose reply has no output. The rejected turn holds the simulated user message and no agent reply. Galtea removes that turn, so it is not scored.
- In both cases the session completes with the stopping reason `The agent ended the conversation (HTTP <code>)`, for example `The agent ended the conversation (HTTP 409)`, and is evaluated.
- A match with no agent answer on the first turn, or in a single-turn test, still fails the session, because there is no conversation left to evaluate.
